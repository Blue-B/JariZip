# 초기 프로토타입 검증 기록

이 문서는 초기 구현에서 실제로 실행한 검증 범위입니다. 모든 운영 환경이나 외부 채용 사이트와의 호환성을 보장하는 인증 문서는 아닙니다.

## 실행 환경

- Linux/WSL, Node.js 22.22.2, npm 10.9.7
- Vite 배포용 빌드의 로컬 미리 보기
- Playwright의 별도 임시 Chromium 컨텍스트. 사용자 브라우저 프로필은 사용하지 않음
- 데스크톱 1440px, 모바일 390px 폭. 화면 캡처는 `docs/preview/`에 보관
- 마이크 관련 자동 검증은 실제 마이크가 아닌 합성 오디오 장치 사용

## 코드·데이터 검증

`npm run typecheck`, `npm test`, `npm run build`를 실행했습니다. 단위 테스트는 **4개 파일, 120개 항목**이 통과했습니다.

확인 범위에는 원문 스냅샷의 독립성, 최신 버전과 제출 버전의 분리, 입력 URL 제한, 잘못된 날짜, 프로토타입 오염 방지, 중복 ID·버전 거부, 끊어진 제출본 참조 거부, 파일·음성 형식과 용량, 백업 왕복, 손상된 저장소 복구 및 쓰기 실패 처리가 포함됩니다.

실제 첫 실행에서 저장 검증용 토큰 읽기 과정 때문에 오류 상태가 잘못 표시되는 문제가 발견되었습니다. 완료된 IndexedDB 쓰기 트랜잭션을 기준으로 저장 상태를 표시하도록 수정한 뒤, 새 브라우저 공간의 첫 실행·프로필 수정·빠른 메모 수정·초기화·새로고침을 확인했습니다.

## 실제 브라우저 검증

`npm run test:e2e`의 **13개 통합 테스트**를 실행해 모두 통과했습니다.

| 흐름 | 확인한 결과 |
| --- | --- |
| 제품 소개 | 캐릭터 버튼 클릭 시 반응, 내 공간 이동, 단축키 검색, Escape로 닫기 |
| 각 작업 화면 | 7개 하위 화면의 제목과 탐색, 1440px·390px에서 최종 레이아웃의 가로 넘침 없음, 모바일 메뉴 열기·닫기 |
| 공고 | 검색·필터 초기화, 수동 공고 추가, 게시일 미확인 유지, 명시적인 수동 접수 확인, 관심 공고 해제, 새로고침 복원 |
| 서류·제출본 | v1 작성 → 제출본 확정 → v2 편집 후에도 면접의 근거와 버전은 v1 유지 |
| 답변·기업 메모 | 답변 저장과 기록 표시, 회사 메모 저장, 새로고침 후 원문 복원 |
| 원본 파일 | TXT 파일 업로드와 같은 제목의 v2 누적, 이전 v1 원본 다운로드가 입력 바이트와 일치 |
| 백업 | 두 서류 버전·제출 기록·답변·메모를 담은 백업을 내려받고 빈 공간에서 복원, 제출본 근거도 유지 |
| 잘못된 백업 | 악성 구조의 JSON을 거부하고 기존 서류 보존 |
| 중첩 창 | 지원 삭제 확인창 종료 후 스크롤 잠금 해제, 원본 서류 유지 |
| 음성 | 버튼을 눌러 합성 오디오 녹음 시작·종료, 답변 저장 전 기록 증가 없음, 저장 후 재생 및 새로고침 복원 |

별도 캡처 절차로 제품 소개와 8개 작업 화면, 주요 모바일 화면을 열어 브라우저 실행 오류와 가로 넘침을 확인했습니다. 작은 화면의 캐릭터와 설명 문구가 겹치지 않도록 캐릭터의 음수 여백도 제거했습니다.

## 캐릭터 인터랙션 추가 검증

캐릭터를 눌러볼 수 있는 안내와 움직임 정지·재개 버튼을 추가했습니다. 정지 중에도 Enter로 캐릭터의 설명을 열 수 있고, 기기의 움직임 최소화 설정을 우선합니다. 지퍼와 종이 반응의 스프링 전환도 이 설정을 따릅니다. 보장되지 않는 오프라인 재접속 문구는 브라우저 내 파일 보관 안내로 바꿨습니다.

이 보완본에서 타입 검사, 배포 빌드, **단위 테스트 120개와 브라우저 통합 테스트 16개**가 모두 통과했습니다. 추가된 2개 브라우저 테스트는 일반 모션에서 정지·재개·키보드 반응과 모바일의 움직임 최소화·가로 넘침을 확인합니다. 데스크톱과 모바일 캡처는 테스트의 임시 결과 폴더에 생성되며 Git에 포함하지 않습니다.

처음 브라우저 검사는 현재 Playwright 버전에 맞는 Chromium이 설치되지 않아 시작하지 못했습니다. `npx playwright install chromium`으로 테스트 브라우저를 설치한 뒤 다시 실행했습니다.

다른 작업 공간의 실행 중인 서버를 잘못 검사하지 않도록 `JARIZIP_TEST_PORT`를 지원합니다. 이번 보완은 별도 작업 트리와 4180 포트에서 기존 미리 보기를 재사용하지 않고 확인했습니다.

```bash
CI=1 JARIZIP_TEST_PORT=4180 npm run test:e2e
```

## 디자인 스킬 검토 반영

클릭되지 않는 설명 카드와 예시 공고 행의 떠오르는 효과·포인터 커서를 제거했습니다. 푸터의 서류 보관함과 지원 보드는 각 작업 화면으로 연결되도록 고쳤습니다. 페이지 내 이동과 본문 건너뛰기는 앱의 해시 경로를 바꾸지 않도록 수정했습니다.

추가 브라우저 테스트는 푸터의 실제 목적지 두 곳과 페이지 내 이동 세 곳을 확인합니다. 이 보완까지 적용한 뒤 위 16개 테스트가 모두 통과했습니다.

## 범위에 포함되지 않은 것

- 외부 채용 사이트 크롤링, 공식 채용 API, 자동 접수 가능 여부 확인
- LLM 실제 호출, 답변 의미·정확성 평가, 합격 확률 예측
- 실제 사람의 마이크·스마트폰 하드웨어, 모든 브라우저의 녹음 코덱
- 로그인·다중 기기 동기화·암호화 저장·운영 서버의 보안 점검
- 일반적인 시각·키보드 점검을 넘어선 전체 접근성 인증
- 실제 서류 제출·이메일 발송·캘린더 연결

이 제한은 앱의 설정 화면과 README에도 표시되어 있습니다.
