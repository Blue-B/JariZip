## 한 건의 지원을 끝까지

공고를 직접 보관하고 서류를 준비한 뒤, 실제로 제출한 버전을 지원 기록에 묶어두세요. 이후 이력서를 수정해도 제출본은 그대로 남습니다. 면접 연습은 그 제출본과 지원 당시 공고를 근거로 이어집니다.

자리집은 브라우저에서 동작하는 웹앱입니다. 계정 없이 시작하며 자료를 별도 서버로 전송하지 않습니다. 처음에는 가상 예시가 들어 있습니다. **설정 → 비우고 내 자료로 시작**에서 빈 공간으로 전환할 수 있습니다. 이 작업은 기존에 입력한 자료도 지우므로 먼저 백업하세요.

## 사용할 수 있는 기능

| 공간 | 실제 동작 |
| --- | --- |
| 제품 소개 | 자리집 캐릭터 지피, 클릭 인사·움직임 정지, 검색·문서 버전·지원 단계 체험 |
| 내 공간 | 저장 자료에서 계산한 현황, 다음 준비 단계, 주간 면접 일정, 최근 서류·활동 |
| 공고 탐색 | 여러 검색어와 필터 조합, 관심 공고, 정렬, 직접 등록·수정, 중복 링크 방지, 접수 상태 수동 기록 |
| 지원 현황 | 단계별 보드·목록, 드래그·메뉴 이동, 준비 메모와 일정, 지원 당시 원문 스냅샷 |
| 서류 보관함 | PDF·DOCX·TXT·MD 업로드, 원본 보관, 텍스트 추출, 편집 시 새 버전, 내려받기·인쇄 |
| 제출본 | 실제 제출한 문서 버전을 선택해 고정. 최신 작업 파일과 제출 원본을 구분 |
| 면접 연습 | 공고·제출본을 근거로 한 규칙 기반 질문, 답변 가이드, 타이머, 글·음성 답변과 연습 기록 |
| 기업 노트 | 회사별 조사 메모, 확인할 질문, 관련 공고 |
| 템플릿 | 한국어 이력서·자기소개서·경력기술서·포트폴리오 작성 틀과 편집 |
| 설정·백업 | 관심 기술·제외 키워드·목표, 원본·녹음을 포함한 JSON 백업과 검사 후 복원 |

서류와 공고 입력창은 저장하지 않은 변경을 버리기 전에 확인합니다. 공고를 수정해도 기존 지원 기록의 스냅샷은 바뀌지 않습니다. 저장 완료는 IndexedDB 쓰기 트랜잭션이 끝난 뒤 표시하며, 저장에 실패하면 성공으로 안내하지 않습니다.

### 아직 연결하지 않은 기능

**실시간 공고 수집, 외부 사이트 자동 접수 확인, LLM 자기소개서 생성·면접 평가, 음성 전사, 계정·클라우드 동기화, 기업으로의 자동 지원 전송은 제공하지 않습니다.** 현재 질문과 기술 비교는 로컬 규칙 기반이며 합격 가능성을 예측하지 않습니다.

모든 기본 회사·공고·서류는 가상 예시입니다. 직접 추가한 공고도 처음에는 `미확인`으로 표시됩니다. 원본 페이지가 열린다는 이유만으로 실제 채용 중이라고 판단하지 않습니다. 게시일을 모르면 비워두고, 마감일이 지난 공고는 마감으로 표시합니다. 사용자가 확인한 상태에는 수동 확인 날짜가 붙습니다.

## 시작하기

Node.js **22.12 이상**과 npm이 필요합니다.

```bash
git clone https://github.com/Blue-B/JariZip.git
cd JariZip
npm ci
npm run dev
```

`http://localhost:5173`에서 엽니다. 배포용 결과물을 확인하려면 다음 명령을 실행하세요.

```bash
npm run build
npm run preview
```

미리보기 기본 주소는 `http://localhost:4178`입니다. 포트가 사용 중이면 다른 프로그램을 종료하지 말고 포트를 바꾸세요.

```bash
npm run preview -- --port 4180
```

Linux/WSL에서는 프로젝트 전용 실행 보조 스크립트도 제공합니다. 로그와 PID는 Git에서 제외된 `.local/`에 생성됩니다.

```bash
npm run preview:start
npm run preview:stop
```

## 자료와 개인정보

이력서, 공고 원문, 메모, 녹음은 **현재 주소의 브라우저 IndexedDB**에 보관됩니다. 서버나 분석 서비스로 전송하지 않으며 폰트와 캐릭터도 앱과 함께 제공합니다. 외부 공고 링크는 사용자가 누를 때만 해당 사이트로 이동합니다.

브라우저 데이터를 지우거나 다른 기기·브라우저·주소로 접속하면 같은 자료가 보이지 않습니다. `localhost`와 `127.0.0.1`도 다른 저장 공간입니다. 한 주소를 꾸준히 사용하고 정기적으로 백업하세요.

저장소와 JSON 백업은 **암호화 보관함이 아닙니다**. 백업에는 문서 원본과 음성도 포함되므로 안전하게 보관하세요. 공용 기기에 개인정보를 넣지 마세요. 가져오기는 병합이 아니라 전체 교체이며 확인이 필요합니다. 형식, 크기, 중복 ID, 문서 버전과 제출본 연결, URL, 파일 데이터 형식을 검사합니다.

손상된 자료를 감지했을 때 조용히 덮어쓰지 않습니다. 용량 부족과 저장 실패도 사용자에게 알립니다. 닫기 확인은 자동 초안 저장이 아니므로 브라우저 강제 종료나 기기 전원 차단까지 복구를 보장하지 않습니다.

### 파일·녹음 제한

- 문서 하나당 최대 **6MB**, 한 번에 5개. PDF는 텍스트 레이어가 있는 최대 60페이지를 처리하며 스캔 문서 OCR은 제공하지 않습니다. HWP/HWPX는 PDF 또는 DOCX로 변환해야 합니다.
- 미리보기는 추출한 텍스트이므로 원본의 표·이미지·레이아웃과 다를 수 있습니다. 원본 파일은 별도로 보관합니다.
- 음성은 명시적으로 마이크 권한을 허용한 뒤 최대 **2분** 녹음합니다. 화면을 나가면 종료하고, 답변 저장을 눌러야 보관합니다. 브라우저별 지원 코덱이 다르며 HTTPS 또는 localhost가 필요합니다.
- 백업 가져오기는 최대 **40MB**입니다. 원본 파일은 Base64 형태로 포함되므로 실제 파일 크기보다 저장 공간을 더 사용합니다.

제출 기록에 연결된 서류의 전체 삭제는 제한됩니다. 지원 기록을 삭제하면 연결된 연습 답변도 삭제하지만 원본 공고와 서류 보관함은 남습니다.

## 개발과 검증

```bash
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e

# 별도 작업 공간에서 다른 미리보기 서버와 섞이지 않게 검사
CI=1 JARIZIP_TEST_PORT=4182 npm run test:e2e
```

브라우저 테스트는 개인 프로필과 실제 마이크를 사용하지 않고 격리된 컨텍스트·합성 오디오로 실행합니다. 제출 버전 보존, 원문 수정, 답변·녹음 저장, 백업 복원, 쓰기 실패, 입력 보호와 모바일 탐색을 검증합니다. [제품 개편 내용과 검증 범위](docs/product-refresh.md)

```text
src/components/       캐릭터, 일정, 대화상자, 서류 편집
src/lib/              자료 구조, 저장·검증, 파일 처리, 예시
src/pages/            제품 소개와 실제 작업 화면
src/styles/           랜딩·작업 공간 스타일
public/brand/         최적화한 지피 이미지
scripts/              미리보기와 화면 캡처
tests/e2e/            실제 브라우저 사용 흐름 검사
```

`docs/preview/`에는 **초기 디자인**의 캡처가 보관되어 있습니다. 현재 UI와 다르며 최신 화면은 앱을 실행해 확인하세요. 검사에서 만든 최신 캡처는 `test-results/` 아래에 생성되고 Git에는 포함하지 않습니다.

## 배포와 기여

`npm run build`의 `dist/`를 정적 호스팅에 배포할 수 있습니다. 상대 자산 경로와 HashRouter를 사용하므로 하위 경로에서도 별도 페이지 재작성 규칙 없이 동작합니다. 공개 도메인·자동 배포 워크플로·서버 API는 기본 설정에 포함하지 않습니다.

지피는 자리집의 지퍼 파우치 캐릭터입니다. 기존 SVG 캐릭터도 소스에 남아 있습니다. [캐릭터 에셋 안내](public/brand/README.md)

버그 제보에는 브라우저와 재현 방법을 남겨주세요. 이력서, 연락처, API 키, 실제 지원 내역 등 개인정보는 공개 이슈·예시 데이터·캡처에 넣지 마세요. [기여 시 확인할 규칙](AGENTS.md)
